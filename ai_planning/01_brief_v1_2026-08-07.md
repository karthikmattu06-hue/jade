# Project brief v1 — Energy-Aware Scheduling for Disaggregated LLM Inference (7 Aug 2026)

*Initial plan, drafted with Claude. Kept unchanged for the record.*

**The project:** characterize the energy profile of disaggregated LLM inference, then build and evaluate a power-aware scheduling policy over it.

**Technical core.** Disaggregated prefill/decode (llm-d, built on vLLM). Prefill: compute-bound, high power, short bursts; degrading it hurts TTFT. Decode: memory-bandwidth-bound, lower power, long duration; degrading it hurts TPOT. Disaggregation creates a control surface for power management that a monolithic server does not have.

**Work plan (v1).**
- Phase 1 (wks 1–3): serve a model under llm-d with vLLM workers; per-GPU power via NVML/DCGM, tagged by pool.
- Phase 2 (wks 4–7): joules per token by phase; sweep prompt length, batch size, P:D ratio; energy–latency Pareto frontier.
- Phase 3 (wks 8–11): under a power cap, compare throttling prefill vs decode; a shedding policy that holds an SLA; report QoS cost per watt shed.
- Phase 4 (wks 12–14): write-up; optional: drive the cap from CAISO/PJM/BPA grid-stress data.

**Fallback ladder.** 1. llm-d on Kubernetes. 2. Ray Serve with a manual P/D split. 3. vLLM native disaggregated prefill, one node, 2+ GPUs. 4. Single-GPU batching and power-cap study. Week-1 dependency: confirm multi-GPU access.

**Outcome:** rung 3 is what runs today (vLLM + NixlConnector on 2 × A100 on SPORC).
